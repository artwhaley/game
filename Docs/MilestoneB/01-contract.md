# Ticket 01 — Milestone B Contract (Frozen)

Date: 2026-08-28. Source: execution packet contracts. This document freezes the
Milestone B scope. Implementation tickets must not deviate from it.

## Separate database lifecycles

- `Content/GameContent.db` — authored content only (existing canonical store).
- `UserProfile.db` — user state, in per-user app data
  (`%LocalApplicationData%/TruthCardGame/UserProfile.db` via
  `UserProfilePaths`). Never merged; no cross-database FKs. Replacing
  GameContent.db must not erase profile data.

## Domain catalogs

- **SessionType**: Id, Title, SortOrder. Session references exactly one
  SessionType. Data, not subclasses. May require zero or more
  SmartToyCapabilityDefinitions; all listed are required.
- **CardTagDefinition**: Id, Title, SortOrder. Card classification only —
  distinct from (now removed) phase tags, Kinks, Equipment, capabilities.
- **KinkDefinition**: Id, Title, SortOrder, optional short description.
- **EquipmentDefinition**: Id, Title, Category (plain text), SortOrder.
- **SmartToyCapabilityDefinition**: Id, Title, Category, SortOrder. Semantic
  capability, not hardware model/protocol.

## User Kink preference

Enum: Love, Like, Torture, DontConsent. Missing profile row = Unconfigured.
Unconfigured is NOT a selectable fifth preference; it is the absence of one.
DontConsent and Unconfigured both hard-exclude Cards carrying that Kink.

## Card

Fields: Id, Title, BodyText. Relations: CardTags[], Kinks[],
RequiredEquipment[], RequiredSmartToyCapabilities[], one owned ActionSequence
(reuses current Action Instance ownership model). New Card default sequence:
1) WaitForContinue, 2) IncrementPhaseProgress +10 — ordinary editable
instances with fresh IDs.

## Phase Card query

Each Phase owns MustHaveAllCardTags[] and MustHaveAnyCardTags[]. ALL empty ⇒
no ALL restriction; ANY empty ⇒ no ANY restriction; both nonempty ⇒ both must
pass. Include-only; no NOT/exclusion in Milestone B (future: status-effect
based exclusion, deliberately deferred).

## Session weighting

Per-Session nonnegative values, default 1.0 each: LoveBase,
LoveHappinessGain, LikeBase, LikeHappinessGain, TortureBase,
TortureUnhappinessGain.

## Eligibility pipeline (ordered)

1. Phase Card Tag query (ALL then ANY)
2. Consent/Kink configuration (any Card Kink with DontConsent or Unconfigured
   ⇒ reject; not overridable by weighting)
3. Equipment (all required items must be owned/available)
4. Smart Toy capabilities (all required must be available)

Machine-readable typed reasons for WPF, not only strings.

## Weighting

`h = Happiness / 100.0`

- LoveScore = LoveBase + LoveHappinessGain * h
- LikeScore = LikeBase + LikeHappinessGain * h
- TortureScore = TortureBase + TortureUnhappinessGain * (1 - h)

Card with zero Kinks: KinkWeight = 1.0.
Love/Like only: arithmetic mean of contributions.
Any Torture Kink present: Torture coefficient 1.0, Love/Like coefficient 0.5;
KinkWeight = (Σ TortureScore + Σ 0.5·PositiveScore) / (TortureCount + 0.5·PositiveCount).
FinalWeight = max(0.01, KinkWeight). Hard impossibility is eligibility's job,
never zero weight.

Default tuning sanity (all 1.0): Happiness 0 → Love 1, Like 1, Torture 2;
Happiness 50 → all 1.5; Happiness 100 → Love 2, Like 2, Torture 1.

## Happiness

Temperature 0–100, session spawn default 50, spawn API may accept override
(persistence deliberately not implemented). Session definitions cannot author
a start value.

## Selection

Weighted RNG using PhaseRun Card RNG only. Candidate ordering deterministic
and documented. GOTO suspends/restores PhaseRun RNG; called Phase gets fresh
run/RNG. No repeat suppression, cooldowns, or deck exhaustion — seams only.
No eligible Card: typed failure naming Session, Phase, executor, query, and
rejection summary. Never skip/relax/silently alter flow.

## SessionType / Session selection

SessionType eligible iff all required capabilities available. Uniform random
choice among Sessions of that type via dedicated session-selection RNG.
Direct "Run Selected Session" remains for author debugging. Consumer flow
(choose type → start) is proof UI, not final game UI.

## Deferred (do not implement)

Anti-repeat/recent-card penalties; decks without replacement; Card
rarity/manual multipliers; boolean eligibility expressions; Kink intensity
scales; Unity Timeline bindings; Buttplug/DG-Lab/TCode; hardware discovery;
content packs; cloud/multi profiles; persistent Happiness; rich-media Card
presentation; mass autogenerated content. Unity only needs compile
compatibility (informational, not gated per user direction).
