# Tickets

The six-phase execution plan for turning the card shell into a game, tracked
as one ticket per phase. Each ticket is a single commit's worth of work with
its own acceptance criteria. Work the tickets in order; a ticket is "done"
only when every acceptance checkbox is checked and the commit is in.

## Status

| # | Ticket | Status |
|---|--------|--------|
| 1 | Runtime services plumbing | Done |
| 2 | Cutscene action (Timeline) | In progress |
| 3 | Choice action | Done |
| 4 | Session/Phase data | Done |
| 5 | SessionDriver core | Open |
| 6 | Screen rework + settings | Open |

Status values: Open → In progress → Done (acceptance met, commit landed).

## Conventions

- Each ticket lists every file it touches — nothing outside that list gets
  changed (agents.md rule 2).
- Commits save the whole project state (agents.md git conventions).
- EditMode tests run with `unity test . --mode EditMode` from the project root.
- Scenes/content are generated by the editor builders; the PoC timeline in
  ticket 2 is the one hand-authored exception (authored in the Timeline window).
